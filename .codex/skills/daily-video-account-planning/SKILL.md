# 视频号日更获客

将每次任务视为独立工作流。唯一目标是通过合规财税内容吸引有真实服务需求的企业经营者；以电商合规服务获客为首要方向，不为播放量偏离获客目标。

## 必须遵守的顺序

1. **重新扫描本地历史库。** 按[知识库读取说明](references/obsidian-history-vault.md)读取当前 Obsidian 仓库。每次都重新列出 `01-历史内容` 下的笔记，并提取全部笔记的 `title`、`publish_date`、`business_line`、`theme`、`content_type`、`audience`、`pain_scene`、`content_goal`；再阅读最近 30 条及拟议同主题笔记的正文。不得使用旧对话、缓存、上次扫描或飞书表格替代当前文件。若仓库不可读取或历史笔记结构无法可靠解析，说明阻碍，在修复前不输出正式选题。
2. **归纳历史覆盖。** 识别已覆盖的业务、客户场景、痛点、内容类型、标题角度、服务机会、近 7 天重复主题和长期缺口。`02-内容地图` 与 `04-内容复盘` 只作辅助；判断必须以当前历史笔记为准，以捕获用户手动修改。
3. **调用 API 采集并筛选当天外部热点。** 外部热点仅用于发现经营问题和衡量选题时效，不得直接作为财税、政策或处罚结论的依据。先评估电商经营主体的合规需求：平台店铺或直播电商的收入与流水、发票和进项、账税一致性、增长临界点、平台数据与申报、个体户或公司主体选择、注销变更及风险自查；随后由 AI 在当次任务中实际调用“外部热点 API 调用清单”规定的接口并处理返回数据。不得以旧结果、记忆、人工推测或网页标题替代 API 调用；若当前运行环境无法调用接口，必须在热点采集摘要中逐项标记原因，不得声称已获取实时热点。涉及政策、税率、优惠、期限、处罚或办理流程时，必须核验当前官方来源；无法确认则不写确定性结论。
4. **提出每日选题。** 输出早、中、晚各 1 条必发选题，另给 2 条备选。3 条必发默认至少 2 条直接服务电商合规，第三条也优先电商；仅在更强的官方热点、明确历史缺口或用户指示下使用其他财税主题。不要固定漏斗或业务轮换。三条必发不得复用同一客户场景、核心痛点或服务机会。
5. **等待选题确认。** 仅在用户明确确认对应时段选题后撰写该条文案；未确认时不生成定稿。
6. **生成文案。** 先完整读取[原始文案生成指南](references/original-copywriting-guide.md)，以其具体规则和最终格式为准；[文案指南摘要](references/copywriting-guide.md)只作快速索引。每条正式方案必须包含 3 个内容标题、1 个常规标题（搜索权重）、1 个 16 字内且无标点或特殊符号的短标题，以及符合指南的正文。仅使用该次已确认主题、用户资料和已核实公开信息。
7. **方案风险评估。** 每条方案在交付前，按[微信常见违规内容概述](https://weixin.qq.com/cgi-bin/readtemplate?lang=zh_CN&t=weixin_agreement&s=video_guide&head=true)及原始文案指南的“风险评估”要求检查。将风险报告附在方案底部，写明风险等级、风险原因、高风险要点和修改建议；高风险内容须先改写再交付。不得因题材属于财税或合规就一律降级，重点评估无依据承诺、虚假或绝对化表述、暗示可代办或保证结果、夸大风险、诱导交易和用户纠纷可能。
8. **等待实际发布反馈。** 用户确认文案后结束制作步骤，不预先写入历史库。等待用户明确说明实际发布了哪条内容。
9. **准备历史笔记。** 用户说明“已更新或已发布某条”时，唯一识别实际采用的时段、标题和正文，按仓库模板生成笔记预览。若无法唯一识别，先询问采用的时段或标题。
10. **确认后写入本地库。** 只有收到用户明确的“确认写入知识库”指令后，才在 `01-历史内容/YYYY/YYYY-MM` 新建笔记，并同步更新相关内容地图、月度复盘、缺口统计和候选清单。不得覆盖同名笔记；发生冲突时先报告。若用户希望自行维护，只输出笔记字段和建议路径，不写文件。

## 外部热点采集与筛选

### 采集顺序与来源边界

1. 完成本地历史库扫描和覆盖分析后，再拉取外部热点；本地历史库仍是账号历史内容、去重和覆盖判断的唯一来源。
2. 依次采集：
   - 抖音：使用公开热榜聚合接口发现热点；再使用已获权限的抖音官方关键词搜索，按“最新”和“点赞”检索垂类内容。
   - 小红书：使用公开热榜聚合接口发现热点；不抓取用户评论、个人资料或需登录访问的内容。
   - 微博：使用公开热榜聚合接口发现热点；如具备授权，可补充微博官方趋势与关键词检索能力。
   - 微信公众号/视频号：使用公开的微信热点话题榜补足微信生态信号。不得将其视为政策或事实依据；没有可用的公开视频号全站热点接口时，如实标记该来源缺失。
3. 抖音官方关键词搜索的初始词池为：`电商报税`、`平台流水`、`平台报送`、`店铺主体`、`个体户`、`电商公司`、`一般纳税人`、`发票`、`进项票`、`无票采购`、`成本票`、`个人卡收款`、`公私账户`、`账税一致`、`直播电商`、`投流费用`、`退款`、`佣金`、`跨境电商`、`出口`、`平台结算`、`公司变更`、`公司注销`、`税务风险`。每周可依据历史缺口、已验证选题和当前有效政策增删词池。
4. 公开热榜聚合接口不可用时，抖音和微博可使用自部署的开源热榜接口兜底；小红书和微信来源缺失时只记录缺失，不得通过保存 Cookie、模拟登录、绕过风控、逆向接口或项目声明仅供学习研究的爬虫补抓。
5. 不在本地仓库保存 API Key、Cookie、账号密码、验证码或用户个人资料。接口凭据仅可在运行环境中临时配置。

### 外部热点 API 调用清单

每次执行“规划选题”任务时，AI 必须在完成本地历史库扫描后、生成候选题前，按下列顺序进行网络 API 调用，并记录每次调用的北京时间、HTTP 成功/失败状态和返回中的原始链接。

1. **三平台实时热榜（必调）。** 以 HTTP `GET` 调用 UApiPro 热榜接口，分别请求：
   - `https://uapis.cn/api/v1/misc/hotboard?type=douyin`
   - `https://uapis.cn/api/v1/misc/hotboard?type=xiaohongshu`
   - `https://uapis.cn/api/v1/misc/hotboard?type=weibo`

   从每个成功响应中读取 `title`、`hot_value`、`index`、`url`、`update_time` 和平台附加标签；只保留排名靠前且与财税电商词池可能相关的条目进入初筛。若接口实际支持的平台 type 与上述命名不一致，应查阅其当前文档后使用有效 type，并记录变更原因。
2. **微信热点（条件必调）。** 当运行环境已安全配置微信热榜服务的 API Key 和请求地址时，调用该服务的微信公众平台热点话题榜接口；读取话题名称、排名和更新时间。未配置 Key、接口返回失败或没有可用的合规公开接口时，在摘要中标记“微信热点：未配置/接口失败/无合规公开接口”，不得用模拟登录或爬虫代替。
3. **抖音垂类验证（条件必调）。** 当运行环境已配置并获授权的抖音 `access-token` 时，针对当前词池中最相关的 3—5 个词，调用抖音官方图文搜索接口 `GET https://open.douyin.com/dy_open_api/v2/search/experience/`：每个词至少按 `sort_type=2`（最新）和 `sort_type=1`（最多点赞）各查询一次，单页 `count` 不超过 10。读取标题、发布日期、点赞量、内容链接或 `item_id`、关键词与排序方式，用于验证该话题是否确有近期讨论。未获授权或无 token 时，标记“抖音官方关键词验证：未配置”，不以猜测补全。
4. **兜底接口（仅在主接口失败时调用）。** 若 UApiPro 的抖音或微博接口失败，并且运行环境已配置自部署 DailyHotApi 的地址，AI 可调用该实例中对应的抖音或微博热点路由。没有已配置实例时，只记录来源缺失；不得调用来源不明的免费镜像站。
5. **调用结果的真实性。** AI 只能依据本次调用实际返回的数据填写“热点采集摘要”。HTTP 错误、超时、授权失败、返回为空和接口未配置都必须如实填写；不得虚构热度、排名、原始链接、发布时间或跨平台验证结果。

### 初筛与淘汰

热点进入候选池前必须同时满足：

- 与电商经营、企业财税、公司主体、平台规则或老板经营决策直接相关；
- 能落到明确的客户场景和痛点，并自然承接合规咨询、代理记账、主体规划或风险排查服务；
- 不依赖未经核验的税率、处罚金额、申报期限、办理流程或政策结论；
- 与近 7 天已发布内容不复用相同客户场景、核心痛点和服务机会。

下列内容直接淘汰，不参与评分：娱乐八卦、纯情绪或与目标客户无关的社会热搜；来源或原始链接无法追溯的信息；必须依靠夸大风险或绝对化措辞才能成立的话题；无法核验且需要作出确定性政策结论的话题。

### 候选题评分

对通过初筛的候选题按 100 分排序：

| 维度 | 分值 | 判断标准 |
| --- | ---: | --- |
| 电商及财税相关度 | 30 | 是否直接触及目标客户的经营问题 |
| 服务承接价值 | 20 | 是否能对应明确的咨询或服务场景 |
| 时效与热度 | 15 | 是否当天发生、排名靠前或持续升温 |
| 客户紧迫性 | 10 | 是否需要立即自查、准备资料或处理 |
| 跨平台验证 | 10 | 是否在两个及以上来源出现，或被关键词搜索验证 |
| 历史内容缺口 | 10 | 是否补足长期未覆盖的场景 |
| 差异化表达空间 | 5 | 是否能避开近期标题和表达角度 |

高分不自动入选；仍须通过历史避重和事实核验。热度只能提高候选优先级，不能替代获客关联和合规判断。

### 事实核验与记录

1. 经营场景题可依据热点和通用合规建议创作，但避免输出未经确认的具体规则。
2. 政策、税率、申报期限、处罚、平台新规、工商税务办理流程等政策/规则题，必须补充当前官方来源；未核验前只可保留为候选，不得进入正式选题。
3. 每日热点记录建议保存至 `03-选题规划/外部热点/YYYY/YYYY-MM/YYYY-MM-DD.md`。仅记录标题或关键词、来源平台、原始链接、排名或热度、采集时间、筛选结论、候选评分和核验状态；不保存用户个人资料、评论全文或批量原始内容。
4. 已核验且可长期复用的政策依据，可在用户确认后归档至 `05-内容素材库/政策资料.md`；未经核验的热点不得归档为政策资料。

### 失败降级

- 单个平台接口失败：标记该来源缺失，继续当天选题，不中断工作流。
- 热榜与财税电商无关：回到内容缺口、客户真实问题和待发布选题，生成常青选题。
- 政策无法核验：改为不含确定性政策结论的经营场景题，或作为备选保留。
- 同一接口连续 3 个选题日不可用：暂停将其作为正式来源，待人工复核后再恢复。

## 历史库规则

- Obsidian 仓库是账号历史内容的唯一来源；不再读取、打开或回填飞书表格。
- 一条已发布视频只建立一篇笔记，按发布日期归档，分类使用 frontmatter 属性。
- `business_line` 表示业务板块，`theme` 表示具体内容主题，不得混用。
- 每日扫描必须覆盖用户可能手动新增、删除或修改的笔记；索引与历史笔记冲突时，以历史笔记为准并修复索引。
- 历史记录用于选题去重和覆盖分析，不作为当前政策有效性的证明。
- 新笔记采用 `00-首页与维护规则/视频内容模板.md` 的结构和 `固定选项库.md` 的统一口径。

## 内容红线

- 不编造政策、案例、数据、金额、比例或处罚结果；不把个案或地方规定说成普遍规则。
- 不制造恐慌，不承诺保证通过、节税效果或零风险，不传播逃税、虚开或规避审核的方法。
- 不写“内部渠道”“特殊关系”，不要求点赞、关注、转发、评论暗号或私信领取资料。
- 不输出镜头、画面、字体、动画或版式建议；正文必须可独立阅读。
